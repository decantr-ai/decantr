# Decantr 3.10 Neutral Benchmark Harness

This directory contains the executable skeleton for the Decantr 3.10 control-versus-treatment experiment. It is intentionally separate from Decantr product packages. The harness treats candidate tarballs, task manifests, evaluator code, model identity, trajectories, reviews, statistics, and claims as bound evidence.

The bundled harness can perform deterministic, no-cost dry runs. It cannot make a real provider request. A fake run proves harness mechanics only; it is not evidence that Decantr improves model output.

Decantr 3.9.4 remains the current stable release. Decantr 3.10 is unreleased and may not be described as value-proven unless the frozen confirmatory gates pass.

## Frozen Inputs

The existing files remain the program authority and are not generated by this skeleton:

- `corpus.json`: 28 pinned repositories, carrying 18 development and 10 qualification acquisition labels. Those corpus labels do not determine task partition or task kind.
- `models.json`: two exact requested model identities and per-run reservation maxima.
- `protocol.json`: 40 tasks, two arms, two models, two repetitions, and 320 total runs.
- `lib.mjs`, `validate-program.mjs`, and `run-day-zero.mjs`: the pre-existing program validator and diagnostic baseline.
- `tasks/development-candidates.json`: 24 public development candidate records.
- `tasks/qualification-index.json`: 16 public opaque qualification IDs and canonical digests only.
- `tasks/freeze-attestation.json`: the public 40-task count, lineage, cutoff, and private-bundle attestation.

The frozen candidate set contains exactly 40 tasks: 24 development and 16 sealed qualification. Every qualification expected change is later than the independent `2026-05-01T23:59:59Z` embargo and both locked official model cutoffs: 2026-02-16 for GPT-5.6 Sol and 2026-01-31 for Claude Fable 5. The May date is a conservative contamination buffer, not a model cutoff.

Independently, the set contains 28 repository tasks covering every corpus repository exactly once plus 12 adversarial duplicate-repository tasks. Repository and adversarial tasks may belong to either task partition; neither the corpus's 18/10 labels nor a 6/6 adversarial split is inferred. Missing tasks, duplicate task IDs, incomplete repository coverage, and arithmetic drift are rejected.

These are frozen candidate records, not yet runnable task manifests. Plan generation will derive partition counts from evaluator-bound plaintext development manifests and the detailed private qualification index after those artifacts are frozen.

## Layout

- `schemas/`: Draft 2020-12 contracts for tasks, plans, runs, trajectories, evaluators, reviews, statistics, the development power pilot, and explicit budget approval.
- `runner/`: canonical JSON, SHA-256 binding, deterministic plan generation, per-run execution, suite execution, parity checks, and cost reservation.
- `environments/`: independently reviewed task toolchains, immutable Linux runtime matrices, workspace preparation, and dependency-tree attestations.
- `container/`: a non-root image with `@openai/codex@0.145.0-alpha.27` and `@anthropic-ai/claude-code@2.1.153`.
- `model-proxy/`: a zero-cost deterministic adapter and reviewed official pricing that remains non-authorizing.
- `evaluator/`: candidate-independent fixed-argv evaluator execution.
- `evaluators/`: authoring, sealed input construction, external container qualification, provenance verification, and task materialization.
- `review/`: blinded artifact preparation and review sealing.
- `statistics/`: sealed-qualification-only paired analysis.
- `audit/`: the fail-closed release evidence gate.

All executable code uses Node built-ins. Process calls use fixed argument arrays with `shell: false`. Content-addressed artifacts are stored as canonical JSON under `<category>/sha256/<digest>.json`.

## Task And Evaluator Contracts

Every plaintext task manifest binds:

- a clean Git base commit and tree;
- the repository, framework, historical project path, corpus pin, and corpus-selected project path;
- one prompt and one shared information entitlement;
- separate control and treatment delivery contexts, both bound to the same entitlement digest;
- allowed and forbidden paths;
- hard request, token, and wall-clock limits;
- a candidate-independent evaluator contract digest.

The historical task base and project path identify the pre-change workspace where the authentic task is executed. They may legitimately differ from the later corpus pin and selected project path, including when an upstream app moved. Both bindings are explicit; ancestry and tree identity are verified instead of requiring false equality.

The shared prompt and information entitlement must be product-neutral. Arm contexts are fixed delivery-only strings, preventing task authors from hiding extra facts in one arm. Qualification prompts, repository identities, expected changes, evaluator details, and oracles stay outside the repository in the hidden bundle. The public qualification index exposes only opaque IDs and canonical SHA-256 bindings.

Evaluator commands declare an executable and argument array. Shell executables and inline Node evaluation are rejected. Evaluators run after the agent, receive a sanitized environment, and emit normalized functional, build, governance, accessibility, and visual metrics. Command output is retained only by digest. A Decantr command, `.decantr` artifact, `DECANTR.md`, or Decantr CLI output cannot be named as an evaluator oracle.

## Evaluator Qualification

Evaluator approval and evaluator qualification are separate gates. Approval records an independent review of the authored contract and oracle. Qualification proves strict polarity and isolation at the exact frozen base and expected revisions.

`qualification-task.mjs --mode host-probe` is a maintainer diagnostic only. It may prepare local worktrees and check strict polarity, but its output carries `materializable: false` and cannot authorize task materialization.

The production path is:

1. Review the evaluator and task environment; lock the runtime matrix and immutable profile image.
2. For a public development task, dispatch `.github/workflows/benchmark-3-10-qualification-input.yml` on `main` with the exact task ID and reviewed proxy-image digest. Its pinned producer acquires the frozen revisions and emits a self-bound authoring seal, exact candidate/environment/matrix/evaluator inputs, minimal Git object packs for base and expected, `request.json`, and `manifest.json` as a three-day artifact. The underlying `pnpm benchmark:3-10:qualification-input -- --mode build ...` command remains available for local diagnostics and rejects tracked or untracked controller drift.
3. Dispatch `.github/workflows/benchmark-3-10-evaluator-qualification.yml` from the same commit with the producer run ID and exact suffixed artifact name. The consumer verifies the source repository, workflow, event, result, branch, and commit before download; it then verifies the complete input manifest, hydrates the exact source trees into a disjoint workspace root, prepares both roles through a registry-only proxy, and evaluates each role offline in the locked image.
4. The workflow signs only `execution-attestation.json` with GitHub OIDC provenance, downloads the bundle, and verifies it against the exact repository, signer workflow, source commit, source ref, SLSA predicate, and GitHub-hosted-runner policy.
5. Run `pnpm benchmark:3-10:qualification-task -- --mode finalize-container ...` against the retained output. Finalization independently verifies the attestation, result artifacts, controller closure, evaluator-source closure, provenance, and strict base-fails/expected-passes polarity before writing a v2 receipt.
6. Materialization independently rechecks that retained chain. The receipt's canonical request and manifest file/self digests, attestation, controller, source-closure, runner-commit, and provenance bindings then flow through the task manifest, run plan, run records, and release audit.

The workflow receives no provider/model credentials. Evaluation networking is Docker `none`; dependency access exists only during the separately attested preparation phase. A caller-supplied digest, local host result, unsigned attestation, self-hosted runner, changed controller tree, changed artifact file, or missing provenance bundle is not qualification evidence.

The checked-in producer accepts public development tasks only. Sealed qualification sources still require a reviewed secret-preserving transfer mechanism before the private qualification path can run. Do not upload private oracle material to a public artifact or commit it to the repository.

## Generate The Run Plan

The randomization seed is mandatory, already committed in `protocol.design.randomizationSeed`, and must be passed exactly:

```sh
node scripts/benchmark-3-10/runner/make-run-plan.mjs \
  --seed e9f877c19cbbb0768a925201782b84d22675484bb5057a5b9e953e8cfc1d5cf7 \
  --tasks-dir "$DEVELOPMENT_TASK_ROOT" \
  --qualification-index "$HIDDEN_ROOT/qualification-index.json" \
  --runtime-matrix "$EVIDENCE_ROOT/runtime-matrix.locked.json" \
  --out "$EVIDENCE_ROOT/run-plan.json"
```

The planner rejects a different seed or a draft runtime matrix, hashes every frozen manifest, task file, and locked matrix, verifies profile counts against all 40 tasks, randomizes task blocks and the eight model/arm/repetition combinations inside each block, emits exactly 320 unique run IDs, and self-binds the resulting plan.

## Fake Dry Run

`run-one.mjs` uses `model-proxy/fake-adapter.mjs` when no adapter command is supplied. The fake adapter preserves requested model identity, records deterministic token counts, costs zero dollars, and never accesses a provider or the network. Every record emitted by this host runner is marked `test-only-host`, `productionEligible: false`; it can test harness mechanics but can never satisfy the release gate.

Each run still requires a clean checkout at the exact task commit and tree, a frozen candidate manifest with locally present tarballs, an evaluator contract, the plan-bound locked runtime matrix, and a verified preparation attestation:

```sh
node scripts/benchmark-3-10/runner/run-one.mjs \
  --plan "$EVIDENCE_ROOT/run-plan.json" \
  --run-id "$RUN_ID" \
  --model-id "$MODEL_ID" \
  --arm "$ARM" \
  --repetition "$REPETITION" \
  --workspace "$FRESH_CHECKOUT" \
  --task-manifest "$TASK_MANIFEST" \
  --evaluator-contract "$EVALUATOR_CONTRACT" \
  --evaluator-root "$HIDDEN_EVALUATOR_ROOT" \
  --candidate-manifest "$EVIDENCE_ROOT/candidate.json" \
  --runtime-matrix "$EVIDENCE_ROOT/runtime-matrix.locked.json" \
  --environment-spec "$TASK_ENVIRONMENT_SPEC" \
  --prepared-environment "$PREPARED_ENVIRONMENT_ATTESTATION" \
  --output-root "$EVIDENCE_ROOT"
```

The arm/model/repetition arguments are required even though they appear in the plan; this prevents an operator from accidentally running a different cell. Before reserving budget, the runner verifies the locked matrix bytes, attestation bytes and self-digest, reviewed environment spec, immutable image digest, lockfiles, clean Git base, and installed dependency tree. It verifies dependencies again after the adapter and evaluator, including ignored `node_modules` changes that Git cannot report. A parity file shared by paired arms binds all of those inputs plus task, evaluator, entitlement, controller, candidate tarballs, base tree, and limits. Any mismatch stops the second arm. Release-eligible model evidence additionally requires a GitHub-hosted split-stage executor with a dedicated minimal agent image that contains no evaluator, expected-patch, qualification-controller, oracle, private-task, or hidden-review bytes. The agent output and trajectory must be content-addressed before a separately attested evaluator image receives the hidden inputs. That executor and agent image are not implemented yet.

`run-suite.mjs` expects one already materialized clean checkout per run at `$WORKSPACE_ROOT/<run-id>` and one verified task attestation at `$PREPARED_ENVIRONMENT_ROOT/<task-id>.json`. It never reuses an agent-mutated checkout. Development task references resolve under `--development-task-root`; sealed references resolve under `--qualification-task-root`; evaluator contracts resolve as `<evaluator-root>/contracts/<task-id>.json`. The suite requires `--runtime-matrix` and `--prepared-environment-root`; it no longer accepts a free-form environment digest. `--run-id` and `--limit` are for fake CI smoke tests only. A partial suite manifest is never release evidence.

The fake adapter recognizes `FAKE_UNSUPPORTED` and `FAKE_FAILURE` in a fixture prompt for failure-path tests. Unsupported targets, adapter failures, provider model substitution, usage-limit breaches, missing evaluators, evaluator failures, and build failures remain explicit run statuses.

## External Adapter Protocol

Paid model invocation is deliberately not implemented. A future audited adapter must be supplied by absolute executable path and is launched as:

```text
<adapter-command> <fixed adapter args> --request <canonical request.json> --response <response.json>
```

The adapter response must use `decantr-benchmark-adapter-response.v1` and contain:

- provider, requested model, and provider-returned model identifiers;
- `completed`, `unsupported`, or `failed` status;
- integer input, output, cached-input, and request counts;
- actual USD cost;
- normalized trajectory events.

Any returned-model mismatch is recorded as `model_substitution`, excluded from pooling, and rejected by the release gate. The benchmark container receives only an audited proxy URL. Provider credentials belong to the proxy and must never be mounted or passed to the runner.

## Paid Execution Boundary

Paid execution requires all of the following before the adapter process starts:

1. `--paid` and an explicit external adapter command.
2. A reviewed `pricing.json` with `paidPricingLocked: true`, exact model rates, and maxima matching `models.json`.
3. A non-expired budget approval bound to the run plan and candidate tarball set, with the exact authorization statement defined by `budget-approval.schema.json`.
4. For qualification runs, a `power-pilot.schema.json` artifact bound to the completed development record set and candidate, demonstrating at least 80% power for the five-point primary effect at alpha 0.05 before qualification execution opens. The qualification budget approval must bind that artifact's SHA-256.
5. A shared budget ledger path.
6. Enough uncommitted aggregate budget to reserve the model's full per-run maximum.

The checked-in pricing file records provider rates reviewed on 2026-07-22. That lock does not authorize spending: paid execution still requires an explicit external adapter, a candidate-bound run plan, a valid human budget approval, and the development power gate before qualification. The ledger uses an atomic directory lock, reserves the full maximum before launch, settles actual cost afterward, and records over-reservation cost as a budget breach.

The protocol maximum is $4,160. A budget approval cannot exceed it. Development pilot runs may use a preliminary approval without a power-pilot binding; before qualification, the approval must be reissued with the same approval ID and the frozen power-pilot digest so the shared ledger and all run records remain connected. Approval is authorization to spend, not evidence of product value.

## Container Isolation

Build and run using `container/Dockerfile` and the restrictions in `container/SECURITY.md`. The entrypoint requires a non-root UID and an empty `/home/benchmark-empty`, strips unapproved environment variables, and rejects provider keys, personal Codex or Claude configuration, MCP configuration, and shell entrypoints. Do not mount a host home, credentials, agent configuration, Docker socket, or SSH agent.

The locked runtime matrix binds the exact Linux amd64 base image, manifest-pinned repository-scoped GHCR benchmark reference, Docker config digest, task runtime and package manager, controller image and agent CLI versions, browser smoke result, complete committed Docker-context/controller closure, GitHub-hosted run identity, and retained OIDC provenance. The runtime workflow publishes and pulls back the exact GHCR manifest before signing; the evaluator receives package read permission only and verifies the pulled config digest before use. Matrix locking independently re-verifies each offline bundle against the exact repository, workflow, commit, main ref, SLSA predicate, and `--deny-self-hosted-runners` policy. The preparation attestation separately binds each task's lockfiles and installed dependency tree. A local self-digest, Dockerfile-only hash, mutable tag alone, or caller-supplied verification result is not runtime evidence.

## Blinded Review

Prepare the reviewer kit only after all qualification run records exist:

```sh
node scripts/benchmark-3-10/review/prepare-kit.mjs \
  --plan "$EVIDENCE_ROOT/run-plan.json" \
  --record-root "$EVIDENCE_ROOT" \
  --qualification-task-root "$HIDDEN_TASK_ROOT" \
  --external-artifact-root "$SCREENSHOT_ROOT" \
  --seed 29a10eb48edeadc7f93d69aa3cdc0e487693afa093d949366068187bd24d212c \
  --reviewer reviewer-one \
  --reviewer reviewer-two \
  --out "$REVIEW_ROOT"
```

The review seed is the deterministic SHA-256 derivative of the committed plan seed; a different value is rejected. The public kit removes run, model, arm, provider, and Decantr metadata; excludes Decantr-generated files from diffs; redacts product identifiers; and strips textual PNG metadata. The private `assignments.json` retains the label mapping and must not be shown to reviewers.

Reviewers score candidate A and B from 0 to 100 and choose A, B, or tie. Seal completed reviews before analysis:

```sh
node scripts/benchmark-3-10/review/seal-review.mjs \
  --assignments "$REVIEW_ROOT/private/assignments.json" \
  --workbook "$REVIEW_ROOT/submitted-workbook.json" \
  --out "$REVIEW_ROOT/private/sealed-review-workbook.json"
```

Exactly two distinct reviewers are required for every assignment. Any preference disagreement requires an adjudication completed before arm and model labels are revealed.

## Statistics

The analyzer reads only tasks listed in the sealed qualification index. Development runs are ignored even if present beside qualification evidence.

```sh
node scripts/benchmark-3-10/statistics/analyze.mjs \
  --plan "$EVIDENCE_ROOT/run-plan.json" \
  --protocol scripts/benchmark-3-10/protocol.json \
  --qualification-index "$HIDDEN_ROOT/qualification-index.json" \
  --record-root "$EVIDENCE_ROOT" \
  --assignments "$REVIEW_ROOT/private/assignments.json" \
  --reviews "$REVIEW_ROOT/private/sealed-review-workbook.json" \
  --seed a2f2079b7e7d53b6b843c05c766e92614b41676068cca1829785ca3a18b42e1a \
  --out "$EVIDENCE_ROOT/statistics.json"
```

The analysis seed is also a deterministic derivative of the committed protocol seed, preventing post-outcome seed selection. The output binds the analyzer source digest. The analyzer averages the two reviewers for each run, averages repetitions within task/model/arm, and then performs paired task-level bootstrap inference separately by model. It reports:

- blind quality lift and 95% paired bootstrap intervals by model;
- governance-violation reduction and intervals by model;
- confirmatory functional noninferiority overall within each model;
- exploratory functional estimates for every model/framework stratum;
- blinded preference aggregated into 32 qualification task/model units by strict repetition majority, with ties excluded, at least 26 decisive units, at least 60% treatment preference among decisive units, and a two-sided 95% Wilson lower bound above 50%;
- median and 95th-percentile token and cost overhead;
- every missing, unsupported, substituted, build-failed, evaluator-failed, or review-incomplete run.

Failures receive conservative functional and governance values and remain in denominators. Missing or changed review-to-record bindings fail the evidence-complete gate.

The functional noninferiority gate is evaluated overall within each model using the protocol's five-percentage-point margin. Framework strata are exploratory unless independently powered. This schema has no independently powered framework artifact, so every framework estimate is emitted with `powered: false`, `gateEligible: false`, and `interpretation: "exploratory-unpowered"`. A one-task stratum therefore remains visible with `n: 1`; its degenerate interval is never presented as passing evidence and does not fail the predeclared overall gate.

## Release Gate

`audit/audit-release-gate.mjs` requires one connected evidence graph:

- candidate tarball bytes and manifest;
- corpus, model, protocol, development-task, sealed qualification, reviewed environment, locked runtime-matrix, and prepared-environment bindings;
- the deterministic 320-run plan;
- all 320 content-addressed run records and trajectory manifests, each carrying signed external split-stage assurance rather than host-only test evidence;
- evaluator results for completed runs;
- one hidden evaluator contract plus bound oracle-source bytes and digest for every sealed qualification task;
- one retained externally executed qualification receipt per task, including its signed execution attestation, controller and evaluator-source closures, exact runner commit, offline provenance bundle, and verification record;
- private assignments, two blinded reviews per qualification comparison, and required adjudications;
- qualification statistics with every predeclared gate true;
- a frozen development power pilot bound to all development records and completed before any qualification trajectory;
- a valid budget approval bound to the candidate and plan;
- claims bound to the statistics, models, observed framework population, limitations, and passing confirmatory gate IDs. Exploratory framework estimates cannot be cited as passing gates.

Run it only against the complete private evidence packet:

```sh
node scripts/benchmark-3-10/audit/audit-release-gate.mjs \
  --corpus scripts/benchmark-3-10/corpus.json \
  --models scripts/benchmark-3-10/models.json \
  --protocol scripts/benchmark-3-10/protocol.json \
  --runtime-matrix "$EVIDENCE_ROOT/runtime-matrix.locked.json" \
  --development-task-root "$DEVELOPMENT_TASK_ROOT" \
  --qualification-task-root "$HIDDEN_TASK_ROOT" \
  --development-environment-root scripts/benchmark-3-10/environments/development \
  --qualification-environment-root "$HIDDEN_ROOT/environments/qualification" \
  --prepared-environment-root "$EVIDENCE_ROOT/prepared" \
  --qualification-index "$HIDDEN_ROOT/qualification-index.json" \
  --plan "$EVIDENCE_ROOT/run-plan.json" \
  --candidate-manifest "$EVIDENCE_ROOT/candidate.json" \
  --record-root "$EVIDENCE_ROOT" \
  --hidden-evaluator-manifest "$HIDDEN_EVALUATOR_ROOT/manifest.json" \
  --assignments "$REVIEW_ROOT/private/assignments.json" \
  --reviews "$REVIEW_ROOT/private/sealed-review-workbook.json" \
  --statistics "$EVIDENCE_ROOT/statistics.json" \
  --power-pilot "$EVIDENCE_ROOT/power-pilot.json" \
  --budget-approval "$EVIDENCE_ROOT/budget-approval.json" \
  --claims "$EVIDENCE_ROOT/claims.json" \
  --out "$EVIDENCE_ROOT/release-gate-audit.json"
```

The audit fails on missing or extra runs, runtime or preparation drift, dependency-tree verification gaps, model substitution, unbound statistics, incomplete review, expired approval, broad claims, or waived claims. **No human-review waiver can authorize the Decantr 3.10 value claim.** The two independent reviews and any required adjudication must actually exist.
