The drift problem

The first AI edit looks fine. The tenth one drifts.

Modern coding agents are fast enough to outrun your product standards. Decantr gives them the context and evidence loop they were missing.

Duplicated components

The agent rebuilds a local button, card, dialog, or form instead of importing the primitive your app already owns.

Inconsistent styling

Inline colors, arbitrary Tailwind values, and one-off spacing sneak past review because each prompt only sees part of the app.

Stale route intent

Pages keep changing while docs, route maps, and design expectations stop agreeing with the code users actually touch.

Scan. Adopt. Verify.

One local loop for every AI edit.

Decantr does not replace your agent or your app. It gives the agent a contract to follow and gives you proof when the implementation drifts.

Scan

Decantr reads routes, components, styling, package signals, and existing project rules without writing anything.

npx @decantr/cli scan

Adopt

It writes a repo-owned contract, scoped context, and an observed baseline while your existing app remains the authority.

npx @decantr/cli adopt --yes

Verify

Project Health emits stable codes, repair IDs, graph anchors, and evidence bundles your AI can repair against.

npx @decantr/cli verify --evidence

Agent-ready context

Give the AI a map before it edits.

Before a coding agent touches a route, Decantr can surface the route contract, local law, style bridge, changed-file impact, and recent health evidence.

  • Contract: product standards, route topology, local UI law, and typed graph context.
  • Context: the route and task details the agent needs right now.
  • Evidence: stable findings and repair prompts after the edit.
